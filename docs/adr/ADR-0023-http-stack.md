# ADR-0023: HTTP stack

- Status: Proposed
- Date: 2026-10-22
- Drafted by: agent (Claude Code, claude-opus-5-5); preference for Gin stated by owner

## Context

The server is in Go (ADR-0014). The HTTP API is defined by an OpenAPI 3.1 contract, `api/openapi.yaml` (ADR-0015). The contract is the source: server code is generated from it, requests are validated against it.

Constraints:

- Easy maintenance; code that people and agents already know well.
- Add no dependency the standard library covers.
- `CGO_ENABLED=0` on all targets (ADR-0020).

Since Go 1.22, the standard library router matches methods and path parameters (`GET /practices/{id}`).

## Options

| Option | Licences | OpenAPI 3.1 | Issues |
|---|---|---|---|
| A. Gin, server generated by `oapi-codegen` (gin target), validation by `kin-openapi` | MIT, Apache-2.0 | `oapi-codegen` v2.8: "initial" 3.1 support; `kin-openapi`: supported | Gin brings many indirect dependencies (e.g. `quic-go`, `mongo-driver`); widely known, many middlewares |
| B. Standard library, server generated by `oapi-codegen` (std-http target), validation by `kin-openapi` | Apache-2.0, MIT | Same as A | Fewer dependencies; middlewares written by hand or taken one by one |
| C. `ogen`, its own generated `net/http` server | Apache-2.0 | Not verified | Fewer users; no Gin |
| D. Huma, code first, contract generated from Go code | MIT | Produces 3.1 | The YAML contract is no longer the source |

Indirect dependency licences: to check with `go-licenses` in CI.

### Generation test

`oapi-codegen` v2.8.0 on `api/openapi.yaml`, Go 1.25, in Docker, 2026-10-22:

| Check | A (gin target) | B (std-http target) |
|---|---|---|
| Generates from the 3.1 contract | yes | yes |
| Compiles, `go vet` clean, `CGO_ENABLED=0`, for linux, darwin, windows on amd64 and arm64 | yes | yes |
| Third-party packages compiled in | 122 | 40 (including `kin-openapi`, for the embedded contract) |
| Request bodies `application/ld+json`, `application/merge-patch+json`, `text/plain` | typed | typed |
| Nullable fields (`type: [T, "null"]`) | pointers | pointers |

Found:

- The JSON-LD key `@context` and the practice field `context` both became `Context` in Go and did not compile. Fixed in the contract with `x-go-name: JSONLDContext` on `@context`.
- Merge patch (RFC 7396): with pointers, `"level": null` (clear the level) and an absent `level` (leave it) are the same. The option `nullable-type: true` generates `nullable.Nullable[T]`, which keeps the difference.
- `x-actions` is ignored by the generator, as expected for our own extension: the actions need their own code and tests.

## Recommendation

B, the standard library with `oapi-codegen` and `nullable-type: true`: same generated code as A, 40 third-party packages compiled in instead of 122. A if Gin middlewares are wanted.
